# Workspace reviews

Read the tracker in core.md. Run a review when overdue and within the current authorization. A reminder is not a completed review. If tooling is unavailable, do the permitted checks and record the missing checks.

## Weekly

1. Read handoffs for projects changed since the last weekly review. Update stale state using project-wrapup.md in record-maintenance mode.
2. Review recorded corrections. If transcript access is approved, run os-corrections-scan.py and inspect each candidate. Save only confirmed corrections with scope and evidence.
3. File clear inbox material. Leave unresolved decisions with the exact question needed.
4. Regenerate the dashboard.
5. Flag projects with no recorded work for 14 days. Do not treat inactivity as completion or archive permission.
6. Run os-health.sh. Assess and fix findings within scope. Do not hide unresolved findings to obtain empty output.
7. Record the Weekly date only after completing the review, or record which steps remain.

## Monthly

1. Check ongoing standards against their current sources.
2. Consolidate duplicate and stale memory. Review records near 100 lines; preserve important facts and evidence.
3. Check routes, client pointers, source-of-truth records, and required templates.
4. Review method changes for verified usefulness. Reverse ineffective changes.
5. Record the result and Monthly date after completion.

A correction promoted to an authoritative rule can become a pointer in the lesson log. Preserve required history and follow explicit privacy-removal instructions.
