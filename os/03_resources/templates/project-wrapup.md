# Project wrap-up

Use when the owner asks to wrap up or finish. A scheduled weekly sweep may run the record-maintenance steps within its existing permission.

1. Identify the named project or the current task's project. Ask only if the target is unclear.
2. Verify completed work. Do not mark an unmet goal complete.
3. Rewrite handoff.md. Keep its eight sections and the 60-line limit. Retain failures and untested conditions.
4. Append the session result to log.md. Update README.md only when stable context or current deliverable pointers changed.
5. Review new corrections, preferences, decisions, and reusable methods. Save explicit facts with date, evidence, and scope. Keep hypotheses separate.
6. Update the dashboard and applicable indexes.
7. File clear project material within the authorized scope. Ask about ambiguous or destructive moves.
8. If the project is complete, write the retrospective and mark Done. Propose archive separately; completion does not authorize a move or deletion.
9. Run applicable checks and record results.
10. If Git is configured and committing is authorized, inspect and commit only intended files. Do not infer remote-push permission.
11. Release project ownership. Report current state, checks, open decisions, next action, learning updates, and exact file paths.

Wrap-up records state. A paused project remains resumable. A finished project has met its defined goal. A weekly sweep must not mark a project complete merely because it is inactive.
