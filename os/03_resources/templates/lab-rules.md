# Design exploration records

Keep one current build per project. Name its path in README.md. Do not infer the current build from words such as final or latest.

Keep one lab per question in the existing labs or experiments directory. Use a date and question in its folder name. Give each variation a theme or purpose name that an independent reviewer can understand. Put property differences in its description.

Each lab README records question, baseline, variations, current status, decision, evidence, and next action. Index the lab where a person can find it without the original chat.

Use Active, Chosen, Parked, Rejected, or Historic for lab review state. A chosen direction is a review decision. Applying it to the current build requires its own scope of authorization and a recorded destination. Keep exactly one current build.

Preserve finished experiments and saved selections according to project retention rules. Do not delete or archive active work without permission.
