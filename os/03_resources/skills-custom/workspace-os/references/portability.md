# Move or restore a workspace

A file copy transfers saved files. It does not transfer every client, credential, plugin, or platform memory store.

## Audit before transfer

1. Identify machine-specific paths and client instruction files.
2. Inventory required tools, skills, plugins, and external source records.
3. Identify memory stores outside this workspace. Read them only within permission.
4. Record which settings can travel and which require fresh setup.
5. Confirm the source and date of environment facts.
6. Test project resume from the selected saved records.

Keep findings in a local migration record. For conflicting facts, preserve evidence and resolve the current source. A newer timestamp alone does not make a fact correct.

## Restore record

List prerequisite tools, file location, client instruction setup, skill restoration, and verification steps. List environment-variable names and recovery procedures without values. Identify content that intentionally does not travel.

Use copy or an approved backup mechanism. Git is optional. Review actual content before configuring any sync or remote. Do not bundle credentials or private transcripts merely because they help local continuity.

At the destination, restore allowed tools and settings. Open the workspace in the intended client. Confirm rule loading, relevant memory, project routing, a saved-state update, and local checks. Record gaps before relying on it for important work.

Do not wipe or retire the source machine from this procedure alone. Decommissioning, credential rotation, and deletion require their own authorization and recovery plan.
