# Maintain the workspace

Use scripts for observable structure. Use reviews for meaning, relevance, and truth. A script cannot verify every working rule.

## Local checks

Run projects-dashboard.sh after project-state changes. Run os-health.sh during reviews. It reports root structure, pointer size, inbox age, memory size, naming, project records, routing, and optional Git information.

Read every reported finding. Empty structural sections mean no configured structural issue was reported. They do not prove complete or correct memory. Do not change unrelated content solely to make output empty.

The weekly reminder reads saved dates and prints when review is overdue. It does not execute a review or run when no process invokes it. The optional Claude Code hook is specific to that client.

The correction scanner reads local Claude Code transcripts only. Obtain permission before accessing them. Treat each printed candidate as unverified evidence. It does not cover every client or infer confirmed preferences automatically.

## Reviews and changes

Use the weekly/monthly checklist. Record dates only after the review work is performed. Keep project handoffs current even when a full review is deferred.

When a durable rule changes, record the approved scope and reason. Preserve prior preference text at the same privacy level when required. Update affected pointers, templates, and an applicable script or review step. Test the change.

Keep the method skill's master in this workspace. If an installed client copy is used, compare it before replacing either version. Do not assume a newer file timestamp identifies the correct source.

Version control is optional. A local commit is not publication approval. Review the selected files before creating a backup or remote. Keep secrets and excluded records out of the selected payload.
