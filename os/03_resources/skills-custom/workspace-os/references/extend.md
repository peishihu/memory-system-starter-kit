# Extend an existing workspace

File by use before adding structure. Outcomes belong in projects. Ongoing standards belong in areas. Reusable material belongs in resources. Inactive material belongs in archive. Unclear material stays in inbox with the decision needed.

Use prefixes for a small new domain. When several related items justify a subfolder, propose it and update affected paths. Three related items is the template's starting threshold, not a format requirement.

A new category must have a defined purpose that existing categories cannot serve. Register it in the AGENTS.md map and add routing for relevant memory. Update the applicable check or review.

Create a topic memory file only for recurring content. Add its route in the same change. Preserve one authoritative record and use pointers elsewhere.

Before adding a client, check its file permissions and supported instruction entry point. Add a thin local pointer where required. Verify it loads AGENTS.md. Keep credentials outside shared configuration.

If a domain cannot share this device, account, or sync destination, use a separate workspace. Copy approved methods only. Do not move personal or organizational records across a boundary without authorization.

Update indexes and handoffs after structural changes. Propose ambiguous moves. Do not delete old material as an implied cleanup action.
